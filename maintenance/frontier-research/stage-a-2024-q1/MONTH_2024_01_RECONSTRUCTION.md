# January 2024 Reconstruction — Stage A

## Month frame

January establishes Stage A's baseline problem: a figure can look complete while uncertainty, inferential nuance, accessibility, or recoverable data semantics remain incomplete.

Coverage: `SEARCH_BOUNDED`.

## J1 — Visualization According to Statisticians, publication record 2024-01-01

Source: https://pure.au.dk/portal/en/publications/visualization-according-to-statisticians-an-interview-study-on-th/

The interview study reports that statisticians use visualization across phases of inferential work and that many participants resist dichotomous thinking. The work motivates richer visual communication around inferential results, including effect-size and uncertainty-related information.

### Stage interpretation

Scientific figures can participate in reasoning before publication, not merely in presentation after analysis. Therefore a figure's role may be exploratory, diagnostic, inferential, communicative, or several at once.

A repository should not infer that a figure intended for one role has automatically satisfied the requirements of another.

## J2 — Uncertainty in humanities network visualization, published 2024-01-12

Source: https://www.frontiersin.org/journals/communication/articles/10.3389/fcomm.2023.1305137/full

This work focuses on representing mathematical and data uncertainty in humanities network visualization.

### Stage interpretation

Network diagrams can visually imply precision even when underlying historical entities/relations or quantitative measures carry uncertainty. The representation of an edge/node is therefore not the same as certainty about that edge/node.

```text
visual object present
!= underlying relation certain
uncertainty omitted from view
!= uncertainty absent from evidence
```

## J3 — Chart4Blind public code object, first code push 2024-01-07

Source: https://github.com/moured/chart4blind_code/commit/8dc19c08c77096229b7839925a279fff8f1475a0

The project's public code appears in January. The documented implementation surface includes SVG/CSV exports, OCR assistance for labels/axes/descriptions, and automatic/manual point entry.

### Why January matters

Before the March paper publication, there is already a concrete code artifact showing that accessible chart conversion requires data extraction plus alternate outputs.

This is a useful temporal distinction:

```text
implementation/public code availability
!= later paper publication date
later paper
!= evidence that January implementation had every later-described property
```

## January synthesis

January combines three perspectives:

1. inferential visualization should avoid false dichotomy;
2. uncertainty is itself part of scientific communication;
3. accessibility may require reconstructing chart structure into non-raster representations.

The shared principle is that **visible pixels are not the complete scientific communication object**.

## January negative space

Not established:

- that every figure should visualize uncertainty explicitly;
- that Chart4Blind January code had all final March paper behavior;
- independent accessibility certification;
- that an uncertainty graphic is statistically calibrated merely because it visually encodes uncertainty.

## Carry-forward

February should test how mainstream plotting systems encode/decode data meaning through guides and how runtime/backend changes affect figure production.
