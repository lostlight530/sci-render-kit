## 3. Turning points and comparison dimensions
1. **Q1 — an artifact has a software stack.** Wrapper major, JS engine, typed-array serialization, patch-level text/diagnostic behavior and grammar/runtime version can affect the observed visualization even if the data and chart title are unchanged. A plotting recipe does not contain all execution semantics.
2. **Q2 — compatibility and delivery are distinct states.** A grammar version can exist before a supported Python wrapper release. Stabilization fixes, export-engine behavior, CDN integrity and ARIA/assistive-state behavior define different evidence boundaries. Availability in a release note is not local implementation or an accessibility certificate.
3. **Q3 — environment and interaction become explicit.** Wheel/runtime/platform distribution identity, browser acquisition, chart export renderer and tooltip/cursor/stack behavior are contextual inputs; reproducing a static screenshot may not reproduce an interaction or accessible experience.
4. **Q4 — dependency and generated-spec identity deepen.** A dependency floor can alter which renderer stack is realizable; Plotly.py's bundled Plotly.js and Altair-to-grammar/spec-generation behavior are different version clocks. This makes “same visualization code” a weak equivalence claim without exact downstream identity.

| Stable analytic dimension | Evidence treated in 2025 | What is NOT established |
|---|---|---|
| data + claim/spec binding | separate from output | scientific conclusion from figure success |
| wrapper / grammar / JS | major, minor and patch identity | cross-version semantic equivalence |
| distribution/runtime | dependency floor, ABI/platform, host | local installed or executed state |
| export pipeline | browser/Chrome, image engine, CDN | repeatability on untested machines |
| human-facing semantics | interaction, tooltip, ARIA | WCAG certification or human comprehension |
| authority | official release objects and Stage analysis | independent cross-environment reproduction |

## 4. Persistent tensions and counter-reading
- A figure can be reproducibly generated and scientifically wrong. Conversely, a scientific assertion may be sound while the presentation fails for a viewer, export target or assistive technology.
- Different renderers/wrappers and grammar objects have distinct feature models. Their changes cannot be merged into a single quantitative field improvement metric.
- Strong competing explanation: our 2025 chronology foregrounds version-state problems because the repository selected release objects to study; it does not independently show that this was the dominant industry research agenda.
- Neither missing independent reproduction nor unselected December novelty can be converted into `DOES_NOT_EXIST` claims.
- Static output equality, JSON-spec equivalence, interactive behavior equality and accessibility equivalence are separate experiments; none was performed for this annual synthesis.

## 5. Year-level synthesis
The 2025 change is best expressed as **provenance of scientific communication**. The first quarter differentiates the declarative recipe and its executing software stack; the middle quarters expose compatibility, delivery, runtime targets, and interactivity; the final quarter emphasizes dependency-floor and generated-spec identity. Once these identities are distinct, two figures that look the same may be non-equivalent as portable, interactive or accessible artifacts, while two byte-different exports may preserve some scientific meaning. Neither proposition is settled by a checksum or a release number.

The useful research outcome is a bounded comparison model:

```text
scientific question / data + uncertainty
 -> claim-to-figure binding
 -> declarative spec + wrapper + compiler/grammar revision
 -> Python dependency floor + platform/ABI
 -> JS renderer + browser/export environment
 -> serialization + static/interactive state
 -> accessibility / recipient / publisher context
 -> observed artifact + separately validated claim
```

A trace of these states improves inspectability but does not validate statistical choices, scientific inference, semantic equivalence or accessibility outcome.
