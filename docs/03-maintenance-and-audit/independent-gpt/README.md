## Cold-start recovery

Before planning or writing, recover:

- current date and evidence window;
- default branch and exact current merged `main` SHA;
- open PRs/live maintenance branches and recent same-surface merges;
- current renderer/runtime implementation and machine-readable configuration;
- latest relevant dated repair/current maintenance record;
- current document-status and maintenance contracts;
- checks actually executed, separately from checks merely available.

For **maintenance-control recovery** use:


For renderer/communication semantics, the most specific implementation, schema/profile/configuration, and active subject contract still own the answer.

## Execution-evidence discipline

```text
checker/scanner source present != executed
executed != passed
render/test history != current execution
passed structural check != scientific validity
contract inspection != runtime verification
```

Unrun checks are `NOT_EXECUTED`. Unobserved scheduler/workflow execution is `EXECUTION_NOT_OBSERVED` when material. Do not fabricate scanner, render, backend, test, publisher, accessibility, or reproduction evidence.

## Repair boundary

When drift is confirmed:

1. identify the owning implementation/configuration/document;
2. identify every machine contract, router, operator guide, or current explanation that must stay synchronized;
3. make the smallest semantically complete repair;
4. preserve dated/historical bodies unless correcting their own point-in-time fact;
5. verify the aggregate branch diff against the exact base;
6. refresh current-main/live-overlap state before delivery.

## Delivery contract

For a real repair:

- use one bounded maintenance branch per repository/owning task when practical;
- coalesce Daily/Weekly labels when they own the same correction;
- record checks run and checks not run;
- create one **Draft PR** after aggregate-diff verification;
- stop for maintainer review;
- do not auto-merge, force-push, or write maintenance repairs directly to `main`.

A Draft PR is a review boundary, not proof of render, test, publisher, accessibility, scientific, or merge success. Final doctrine and merge authority remains with the maintainer.

## Public boundary

Do not publish or reconstruct private Jules prompts, repository memory, hidden reasoning, credentials, or unrelated operator context. Public repository governance may preserve the effect of a rule without copying private control text.
